SECTION 1: WHAT D2OC ALGORITHM DOES
================================================================================

D2OC IS AN EXPLORATION ALGORITHM that decides WHERE the robot should explore.

EXECUTION FLOW:
===============
1. Robot moves (Nav2 controls it)
2. LiDAR scans environment continuously
3. D2OC reads scans and builds density map
4. D2OC calculates entropy (information value) at each location
5. D2OC identifies high-entropy regions (unexplored areas)
6. D2OC decides WHICH region to explore next (this is the algorithm)
7. D2OC publishes goal pose to /exploration/goal
8. Nav2 sees new goal and navigates to it
9. Loop repeats every ~1 second

INPUT:
======
- /scan (LiDAR scans @ 10Hz from RPLiDAR)
- /odometry/filtered (Robot pose @ 20Hz from EKF)
- /tf (Transforms for coordinate conversions)

OUTPUT:
=======
- /exploration/goal (PoseStamped @ 1Hz)
  Single goal: "Next place to explore"

WHAT D2OC DECIDES:
==================
"Of all the unexplored areas (high entropy), which one should I explore next?"

D2OC's Decision Logic:
1. Build occupancy probability grid (density map)
   - Free cells (observed, no obstacles)
   - Occupied cells (observed, has obstacles)
   - Unknown cells (never observed)
   - Confidence level in each classification

2. Calculate entropy at each cell
   - High entropy = uncertain, unexplored
   - Low entropy = certain, well-mapped

3. Find regions with highest entropy (unexplored areas)

4. Select ONE region as next exploration goal
   - Weighted by: information gain, distance, accessibility
   - Goal is published to Nav2

5. Nav2 navigates to that goal
   - Uses its own planner and controller
   - D2OC doesn't control how robot gets there

6. Repeat (new goal every ~1 second)

STEP 4: IMPLEMENT density_map.py
=================================
Time: 2-3 hours

File: d2oc_algorithm/src/d2oc_algorithm/density_map.py

Purpose:
- Build and maintain occupancy probability grid from LiDAR scans
- Track confidence in each classification
- Support ray-casting to mark free/occupied cells
- Convert to ROS OccupancyGrid for visualization

Key Class: DensityMap

Responsibilities:
- Initialize grid (100m x 100m @ 0.2m resolution)
- Convert world coordinates ↔ grid coordinates
- Update from LiDAR scans (ray-casting)
- Store occupancy (probability of obstacle)
- Store confidence (certainty of classification)
- Decay old observations over time
- Export to OccupancyGrid message (RViz visualization)

Key Methods:
1. __init__(width, height, resolution)
   - Create 500x500 grid
   - Initialize with 0.5 occupancy (unknown)
   - Initialize with 0.0 confidence (no observations)

2. world_to_grid(world_x, world_y) → (grid_x, grid_y)
   - Convert world frame to grid indices

3. grid_to_world(grid_x, grid_y) → (world_x, world_y)
   - Convert grid indices to world frame

4. update_from_scan(scan_msg, robot_x, robot_y, robot_theta, confidence)
   - For each LiDAR ray:
     a. Calculate angle in world frame
     b. Calculate hit point (range * cos/sin of angle)
     c. Ray-cast from robot to hit point
     d. Mark all cells along ray as FREE (occupancy = 0.0)
     e. Mark hit point as OCCUPIED (occupancy = 1.0)
   - Use Bayesian update for occupancy probability

5. get_occupancy(grid_x, grid_y) → float [0.0, 1.0]
   - Return occupancy probability at cell
   - 0.0 = free space, 1.0 = occupied

6. get_confidence(grid_x, grid_y) → float [0.0, 1.0]
   - Return how certain we are of this classification
   - 0.0 = no observations, 1.0 = many observations

7. to_occupancy_grid() → OccupancyGrid
   - Convert internal representation to ROS message
   - For visualization in RViz

Data Structures:
- self.occupancy: 2D numpy array (float32)
  Shape: (500, 500)
  Range: [0.0, 1.0]
  Value: Probability of obstacle at that cell

- self.confidence: 2D numpy array (float32)
  Shape: (500, 500)
  Range: [0.0, 1.0]
  Value: Certainty of occupancy classification

- self.observation_count: 2D numpy array (int)
  Shape: (500, 500)
  Value: Number of observations for each cell


STEP 5: IMPLEMENT entropy_calculator.py
========================================
Time: 1-1.5 hours

File: d2oc_algorithm/src/d2oc_algorithm/entropy_calculator.py

Purpose:
- Calculate Shannon entropy from occupancy probabilities
- Identify high-entropy (unexplored) cells
- Rank cells by information value

Key Class: EntropyCalculator

Responsibilities:
- Compute entropy: H(p) = -p*log2(p) - (1-p)*log2(1-p)
- Find high-entropy cells
- Rank cells by entropy value
- Support information gain calculations

Key Methods:

1. entropy(probability) → float
   Formula: H(p) = -p*log2(p) - (1-p)*log2(1-p)
   
   Examples:
   - p = 0.0: H = 0.0 (certain: free space)
   - p = 0.5: H = 1.0 (uncertain: maximum entropy)
   - p = 1.0: H = 0.0 (certain: occupied)
   
   Interpretation:
   - High entropy = uncertain, unexplored, WANT TO EXPLORE
   - Low entropy = certain, well-mapped, DON'T NEED TO EXPLORE

2. find_high_entropy_cells(density_map, threshold) → list of (x, y, entropy)
   - Iterate through all grid cells
   - Calculate entropy at each cell using density_map.occupancy
   - Keep cells with entropy >= threshold
   - Return as list of (world_x, world_y, entropy_value) tuples
   
   Example: threshold = 0.8
   - Returns all cells with H >= 0.8
   - These are unexplored regions

3. rank_cells_by_entropy(cell_list, density_map) → sorted list
   - Take list of cells
   - Calculate entropy for each
   - Sort by entropy (highest first)
   - Return sorted list


STEP 6: IMPLEMENT d2oc_algorithm.py
====================================
Time: 2-3 hours

File: d2oc_algorithm/src/d2oc_algorithm/d2oc_algorithm.py

Purpose:
- Core D2OC decision logic
- Takes density map and entropy values
- Decides where to explore next

Key Class: D2OCAlgorithm

Responsibilities:
- Get high-entropy cells from entropy calculator
- Filter cells by distance (only reachable ones)
- Score each high-entropy cell
- Select best cell as next goal
- Return goal pose

Key Method: compute_exploration_goal(density_map, robot_x, robot_y, costmap)

Algorithm Steps:
1. Get all high-entropy cells
   cells = entropy_calculator.find_high_entropy_cells(density_map, threshold=0.8)

2. Filter by distance
   - Only consider cells within max_distance (e.g., 20m from robot)
   - This ensures reachable goals

3. Filter by accessibility
   - Check if each cell is in free space (not in obstacle)
   - Use costmap for safety check

4. Score each candidate
   For each cell:
     score = entropy_value - α * distance
   
   Where:
   - entropy_value: How much we'd learn (high = good)
   - distance: How far away (close = good)
   - α: Weight parameter (e.g., 0.1)
   
   Example scoring:
   Cell A: entropy=0.95, distance=5m  → score = 0.95 - 0.1*5 = 0.45
   Cell B: entropy=0.90, distance=3m  → score = 0.90 - 0.1*3 = 0.60
   Cell C: entropy=0.85, distance=1m  → score = 0.85 - 0.1*1 = 0.75
   → Choose Cell C (highest score)

5. Return best cell as goal
   - Convert grid coordinates to world coordinates
   - Create PoseStamped message
   - Return goal

Key Parameters:
- entropy_threshold: 0.8 (0-1, what counts as "high entropy")
- max_goal_distance: 20.0 (meters)
- distance_weight: 0.1 (how much to penalize distance)
- min_confidence: 0.3 (only explore where we have some observations)


STEP 7: IMPLEMENT d2oc_node.py
===============================
Time: 3-4 hours

File: d2oc_algorithm/src/d2oc_algorithm/d2oc_node.py

Purpose:
- Main ROS2 node
- Orchestrates density map, entropy, and decision logic
- Subscribes to sensors
- Publishes exploration goals

Key Class: D2OCNode (inherits from rclpy.node.Node)

Responsibilities:
1. Initialize components (density map, entropy calculator, algorithm)
2. Subscribe to sensors
3. Update density map from LiDAR scans
4. Compute next goal periodically
5. Publish goal to /exploration/goal

Subscriptions:
- /scan (LaserScan @ 10Hz)
  Action: Update density map

- /odometry/filtered (Odometry @ 20Hz)
  Action: Store robot pose and orientation

- /local_costmap/costmap (OccupancyGrid @ 5Hz)
  Action: Store for goal validation

TF Transforms:
- Listen to /tf for robot pose in map frame
- Convert robot pose when processing scans

Publications:
- /exploration/goal (PoseStamped @ 1Hz)
  What: Next location robot should explore
  
- /d2oc/density_map (OccupancyGrid @ 1Hz)
  What: Visualization of known/unknown areas
  For: RViz display

Main Loop (Timer @ 1Hz):
1. Check if we have robot state and costmap
2. Call d2oc_algorithm.compute_exploration_goal()
3. If goal is valid:
   - Publish to /exploration/goal
   - Log success
4. If no valid goal:
   - Log warning
   - Try again next cycle

Callbacks:
1. scan_callback(msg):
   - Get latest robot pose from /tf
   - Call density_map.update_from_scan()
   - Update uses confidence = 0.9 (LiDAR is reliable)

2. odom_callback(msg):
   - Store robot position and orientation
   - Needed for goal distance calculations

3. costmap_callback(msg):
   - Store costmap for validation
   - Used to check if goals are in free space

SECTION 6: WHAT MAKES D2OC DIFFERENT FROM OTHER ALGORITHMS
================================================================================

D2OC Algorithm Characteristics:
- Uses DENSITY MAP (probabilistic occupancy grid)
- Uses ENTROPY (information-theoretic uncertainty measure)
- Scores goal by: entropy_value - distance_penalty
- Weights exploration by information gain
- Adaptive: explores high-entropy areas preferentially
- Principled: based on information theory

Frontier-Based (for comparison):
- Finds boundary between known and unknown
- No density weighting
- Explores nearest frontier cluster
- Faster but less sophisticated

Information Gain (for comparison):
- Similar concept to D2OC
- Scores by expected observation value
- May use different weighting

Next-Best-View (for comparison):
- Most sophisticated
- Accounts for occlusions
- Computationally expensive
- May be too slow for Jetson

D2OC is the BASELINE algorithm you're testing against these alternatives.
